# Branvik Emulator Updater 0.1.0

Исходный плагин Playnite: C#, WPF, .NET Framework 4.6.2, PlayniteSDK 6.18.0.

## Сборка
Откройте Branvik.EmulatorUpdater.csproj в Visual Studio с компонентом разработки классических приложений .NET и SDK .NET. Восстановите NuGet-пакеты, затем выполните Release Build.
Команда из каталога проекта: dotnet build -c Release
Reference Assemblies 4.6.2 загружаются через NuGet. Требуется доступ к api.nuget.org.

## Установка для разработки
Закройте Playnite. Скопируйте содержимое bin/Release/net462 в отдельный подкаталог Extensions вашей установки Playnite (для обычной установки обычно %AppData%/Playnite/Extensions/BranvikEmulatorUpdater). extension.yaml и Branvik.EmulatorUpdater.dll должны лежать рядом. Перезапустите Playnite. Откройте главное меню → Branvik Emulator Updater.

## Отладка в Visual Studio
В Properties/launchSettings.json настроен профиль Playnite Desktop: он запускает установленный Playnite с отладчиком. Путь указан для текущего компьютера; при переносе проекта измените executablePath и workingDirectory.
Выберите конфигурацию Debug и профиль Playnite Desktop рядом с кнопкой запуска. Нажмите F5: Visual Studio соберёт проект и запустит Playnite. Каталог bin/Debug/net462 должен быть добавлен в Playnite → Для разработчиков → Внешние расширения.
Для следующей итерации используйте Shift+F5 (остановить отладку), внесите изменения и снова нажмите F5. Повторно запускать Playnite вручную не требуется. Если Playnite был запущен отдельно, полностью закройте его перед первым F5, включая значок в трее: уже работающий экземпляр может удерживать DLL или перехватить запуск. Горячая перезагрузка плагинов Playnite не поддерживается.
Поставьте точку останова в UpdaterPlugin или обработчике меню и откройте расширение. Если профиль не появился, перезагрузите проект в Visual Studio. Запуск через F5 и попадание в точку останова требуют проверки в самой Visual Studio.

## Использование
При открытии окна читается Database.Emulators. Названия и каталоги автоматически синхронизируются по ID; удалённые из Playnite записи исчезают при следующей синхронизации. Кнопка синхронизации перечитывает базу. База Playnite не изменяется.
«Добавить эмулятор вручную» открывает выбор папки. «Удалить эмулятор» удаляет выбранные ручные записи, без удаления файлов; при смешанном выделении кнопка отключена.
В столбце GitHub укажите owner/repo официального проекта. Автоматическое угадывание репозитория намеренно отсутствует. В установленный тег можно вписать точный tag установленного выпуска. Изменения сохраняются автоматически при вводе. Нажмите «Проверить» для выделенных строк.
«Проверить» по умолчанию запрашивает последний стабильный GitHub Release. Галочка «Включать предварительные» включает prerelease/nightly: выбирается самый свежий по published_at среди первой страницы из 100 выпусков, без черновиков. Более новый стабильный выпуск также может быть выбран. Это не отдельный nightly-only канал. Настройка сохраняется для каждой строки.
Настройки сохраняются штатным SavePluginSettings Playnite. Локальные папки не передаются в сеть; GitHub получает имя репозитория.

## Границы версии
Установка обновлений доступна для PCSX2/pcsx2 и RPCS3/rpcs3-binaries-win; для остальных эмуляторов пока доступна только проверка выпусков. Локальная версия не извлекается из exe автоматически. При неизвестном установленном теге показывается только последний выпуск; различающиеся нечисловые теги требуют ручного сравнения. GitHub без авторизации ограничивает частоту запросов. Отсутствие стабильного релиза отображается отдельно. Каталог Playnite отображается как сохранён в базе, включая переменные путей.

## Проверка

После сборки: проверить открытие меню, импорт записей Playnite, добавление/удаление ручного каталога, сохранение после перезапуска, успешный запрос релиза, неверный репозиторий, работу без сети и закрытие окна во время проверки.

## Установка обновлений PCSX2
Закройте PCSX2, выберите его строку и нажмите «Обновить». Требуется официальный репозиторий PCSX2/pcsx2, абсолютный каталог с pcsx2-qt.exe и установленный 7-Zip в Program Files. Выбирается единственный архив pcsx2-*-windows-x64-Qt.7z или .zip; symbols и установщики не запускаются. Выпуск перечитывается с учётом галочки предварительных сборок. Подтверждение показывает тег, файл и каталог. Возможна установка более старого тега при смене канала — проверяйте его перед подтверждением.

Архив скачивается во временную папку, проверяются размер и SHA-256 (если GitHub её предоставил), затем распаковывается отдельно. Ограничения: 512 МиБ загрузки и 2 ГиБ распакованных данных. Заменяемые файлы копируются в соседний BranvikBackups/<идентификатор>/files. Сохраняются настройки, BIOS, карты памяти, сохранения и другие пользовательские каталоги из списка Protected в UpdateInstaller.cs. Старые файлы, отсутствующие в архиве, не удаляются. При обычной ошибке копирования выполняется автоматический откат; при невозможности отката выводится путь резервной копии. Защита от отключения питания/завершения процесса не гарантируется.

Ручное восстановление: закройте PCSX2, скопируйте содержимое files из нужной резервной копии обратно в каталог из installation.txt с заменой. added-files.txt содержит добавленные обновлением файлы: удалите их, только если они не нужны. Затем исправьте установленный тег в таблице. Автоматической кнопки отката пока нет.

Проверка: сборка успешна; tests/Installer.ps1 проверяет замену, резервную копию, сохранение настроек, добавление файлов, отклонение опасных путей и откат при блокировке файла. Реальная загрузка/распаковка релиза и установка через окно Playnite ещё не проверены. Тесты работают только в собственных каталогах tests/fixtures-*.

Общая кнопка «Обновить» доступна только при непустом выделении. Ctrl+щелчок выбирает отдельные строки, Shift+щелчок — диапазон. Ctrl+щелчок по выделенной строке снимает её выделение. Выбранные записи обрабатываются последовательно, с подтверждением для каждой поддерживаемой установки. Отказ или ошибка одной записи не останавливает остальные. Неподдерживаемые эмуляторы пропускаются с пояснением. Итоговое окно содержит результаты всей операции.

## RPCS3
В столбце GitHub укажите RPCS3/rpcs3-binaries-win. Каталог должен содержать rpcs3.exe. Выделите строку (можно вместе с PCSX2), нажмите «Обновить» и подтвердите архив/тег. Для RPCS3 используются Windows x64 архивы rpcs3-v*_win64_msvc.7z и прежний формат rpcs3-v*_win64.7z; при неоднозначном выборе установка блокируется. Требуется 7-Zip. Источник загрузки ограничен выбранным поддерживаемым репозиторием.
Перед установкой закройте RPCS3. Сохраняются все каталоги dev_* (игры, прошивка, сохранения), config, GuiConfigs, patches, savestates и файлы конфигурации. Резервные копии и откат работают как для PCSX2. Тег build-<hash> может отличаться от версии в названии архива; хранится точный тег GitHub. Галочка предварительных сборок означает метку prerelease GitHub, а не наличие стабильной версии RPCS3.
Сборка и tests/Rpcs3.ps1 проверяют выбор архива, отказ при неоднозначности, сохранение пользовательских данных, замену бинарного файла и резервную копию. Дополнительно пройдены прежние тесты установки и выбора релиза. Реальная установка RPCS3 через Playnite не проверялась.
Нижняя панель: слева иконки «Синхронизация», «Проверить», «Обновить»; справа «Добавить эмулятор вручную», «Удалить эмулятор». Подсказка появляется при наведении, названия доступны экранному диктору. Проверка и обновление доступны только при непустом выделении. Проверяются только выделенные строки. Удаление доступно, если все выбранные строки добавлены вручную. Кнопок сохранения и сброса выделения нет: текст и галочки сохраняются автоматически при изменении значений.
